# R0 Source-Only Audit

## Stage 22 evidence boundary

The current Stage 22 closure is preserved as historical source-only audit evidence. It records a prior closure narrative and helper/static audit outputs, but it does not establish production DNS-FSI closure in the `xcompact3d` production path.

## Source-only audit versus production DNS-FSI validation

A source-only audit reviews files, helper scripts, static text, synthetic cases, or candidate logic without proving that the production executable builds and advances the intended coupled physics. Production DNS-FSI validation requires real build output, real run output, real MPI execution where claimed, and DNS/FSI evidence generated by the production solver path.

## Synthetic/static checks are not substitutes

Synthetic metrics, Python helper checks, and static text checks cannot replace actual `mpirun`, build, or DNS output. They may be useful as development aids, but they must not be cited as proof of real production execution or production-ready DNS-FSI closure.

## Claims that cannot currently be made

The following items cannot currently be claimed as complete production closure:

* real two-way FSI production integration,
* real IBM force spreading into RHS,
* real structure advancement in production loop,
* real wall contact production coupling,
* real fibre-fibre collision production coupling,
* real restart of fibre state,
* real statistics/visualization of fibre state, and
* real `np=1/2/4` MPI consistency.
